# Separate engineering qualification from attachment governance and report rendering

The private case bundle records unsigned, self-attested internal evidence: a real or synthetic case, immutable calculation runs, per-run independent comparisons, discrepancy dispositions, reviewed artifacts, and explicit adoption receipts. Each comparison assertion extracts its value through a JSON Pointer from separate production-result and independent-reference JSON artifacts; the normalized comparison binds both machine-readable artifacts, the human reference, and the production output by SHA-256. Reviewed and rendered artifacts must visibly retain the same fixed 16-hex calculation fingerprint. A PDF additionally binds its sibling canonical-render evidence by relative path, bytes, and SHA-256, and is accepted only when the attachment inspector reports verified visibility rather than text-layer-only extraction. A synthetic case or one to two pilot cases may contribute G1 evidence but cannot establish a tool-wide verification domain; G2 and G3 require a real case and remain limited to the same run and artifact. Existing formal-attachment governance continues to prove document identity, approval metadata, packaging integrity, and archive lineage; it must not infer engineering equivalence from `ready`. A report renderer such as docxtpl may consume only same-run G3-adopted artifact data without recalculating results or copying approval. Internal G1/G2/G3 records do not authenticate the reviewer, constitute certification, or provide legal sign-off. This intermediate boundary costs one additional contract and review step, but prevents per-page browser drafts, package integrity, synthetic fixtures, pilot cases, or editable Word output from becoming an accidental source of engineering truth.

The beam-column moment pilot is the first production-backed bridge into this bundle. It executes the V1.3 production adapter and a separately implemented, same-repository closed-form oracle for the registered 88-field `momentPriorTestSmrfPass` case, converts all 71 fixed-policy catalog assertions plus eight previously unregistered decision gates into 79 JSON Pointer result comparisons, preserves the selected-plane and `completeJointDesign=false` boundary, and seals only a synthetic G1 package outside the repository. It rejects dirty Git sources and observable Node or Git runtime injection, rejects repository and private-info attributes policies before status, normalizes the governed physical UTF-8 source line endings and compares them directly with raw committed content without checkout filters, binds a resolvable commit object, governed Git blobs and committed-content hashes before and after isolated calculator execution, writes criteria evidence before execution, and cross-binds CF, QRF, comparison V2 data, visible boundaries, and the decision receipt. A trusted parent process and trusted Node and Git executables remain an external premise: a Node process cannot prove that arbitrary code did not already control it before this pilot loaded. The same-repository oracle can reveal software drift but cannot eliminate a shared code-interpretation error. Therefore its tight catalog tolerances are not real-case acceptance criteria, and the bridge cannot create G2, G3, AISC 358 prequalification, complete joint design, or legal sign-off. A real case must set its criteria before execution, use an external hand calculation, independent spreadsheet, or third-party result, and add human G2 applicability and G3 artifact-adoption decisions.

The real-case intake gate deliberately precedes any production execution. Its producer emits `beam-column-moment-real-case-intake.v1 / candidate-unvalidated`, which must be copied out of the synthetic workspace into a separate private workspace that neither contains nor is contained by the repository. The gate closes the 88-field type and fixed-scope contract, real-case identity, pre-execution criteria, governing authority labels, case-source artifact, and separate human-readable plus machine-readable evidence from an external hand calculation, independent spreadsheet, or third-party system. Duplicate JSON keys, path or physical-file ambiguity, digest mismatch, and verification races fail closed. Assessment is read-only; only explicit `--seal-readiness yes` may create a non-overwriting receipt. Its sole success state is `intake-complete-manual-g1-work-required`, with calculator execution, engineering comparison, G1, G2, G3, complete-joint design, attachment approval, Pages publication, and legal sign-off all false. Production execution and comparison belong to a later real-case G1 runner. The new intake gate does not accept a legacy empty template as a candidate, while already sealed legacy synthetic G1 bundles remain verifiable under their original case-bundle contract and must not be rewritten.
