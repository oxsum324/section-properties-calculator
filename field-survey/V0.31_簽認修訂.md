# V0.31 簽認修訂與附件規則

本版依使用者確認的七項規則修正簽認保存與附件輸出。

| 作業 | 本版規則 |
| --- | --- |
| 已簽內容變更 | 保留原簽認，建立新的修訂與簽署名單。原簽名只對應原內容。 |
| 純排序、編號或版面變更 | 沿用原簽認。採用照片集合固定，照片與位置識別碼仍可追溯。 |
| 多次會勘 | 外部附件只附本戶最後一次實際會勘的簽認。 |
| 最後一次未簽或內容已變更 | 顯示「本次尚未簽認」，不帶入前次簽章。 |
| 公設按樓層或冊次分段 | 簽認置於該公設第一段一次，列出實際樓層與範圍。其歸屬在完整分冊計畫固定。 |
| 舊版簽認 | 原資料保留。版本與比較歷程供內部追溯，外部附件不增加版本追溯提示。 |
| 拒簽或不在場 | 記錄原因，由本版有效鑑定人員簽名見證後可輸出；不能保留已失去有效見證的拒簽紀錄。 |

## 簽認與媒體保存

每份新簽認具有獨立內容快照、內容指紋與修訂來源。快照保存案件與戶別識別、簽認欄位及該次會勘紀錄。媒體以 SHA-256 對應原檔，還原或彙整重新配置識別碼時，原快照保持不變。

簽認快照、比對與歷史保留集中於 signoff-content.js，由 model.js 保持原有匯出介面。其餘資料與畫面修改從 src/model.source.js 與 src/signoff-ui.source.js 進行，再以既有建置器產生壓縮執行檔。儲存邊界拒絕覆寫既有內容或簽章，並維持案件版次衝突檢查。

目前紀錄刪除照片時，已簽快照引用的原檔仍會保留於案件備份。新簽認的內容指紋排除頁碼、照片與紀錄順序、位置編號及修改時間，採用固定字元排序，避免裝置語系造成假變更。

新舊照片編號歷程隨案件保存，可由同一筆紀錄與媒體識別碼對照。附件編號對照 JSON 另含本次編號變更表。既有附件編號對照 JSON 保留來源案件版次、紀錄 ID、媒體 ID 及本次照片編號。原已下載的 HTML 與編號對照不會因後續排序改變。

## 相容性

本版為 V0.31.0。IndexedDB 與 .csurvey 格式均升為 19，可讀舊格式 1～18。更新前關閉其他分頁及主畫面視窗。舊程式不能繼續開啟新版資料庫或讀取新版備份。

舊版簽認不會被補造為已經保存的原始快照。舊摘要與簽章繼續保留，內部比較基準用來區分後續實際內容變更與純排版變更。

## 本機驗收

- node --test field-survey/tests/model.test.js 包含簽認修訂測試，共 116 項。
- node field-survey/tests/run-in-memory.cjs v031 v030 v0303 檢查實際表單、IndexedDB、HTML、PNG、觸控簽名、修訂保存、最新會勘選取、公設分層、分冊目錄、歷史還原及舊寫入器拒絕。
- node field-survey/tests/browser.test.js 保留完整瀏覽器及離線快取測試，並加入 V0.31 流程。
- node field-survey/tests/upgrade-v08.cjs 保留歷史版本升級測試，新增格式 18 的 V0.30.3 來源。

run-in-memory.cjs 以本機檔案回應瀏覽器請求，使用真實 DOM、IndexedDB 及畫布。它封鎖 Service Worker，不驗證網路、離線快取或完整升級。完整流程受環境阻擋時，不能以這項測試替代完整流程通過。

本輪沒有以實體 iPhone 或 Android 驗證，也未發布至正式網站。合成測試與收據位於 output/field-survey-validation/ 及 output/pstack-condition-survey-review-20261025/。

發布候選補正了首頁衍生導覽與分類頁，並修正正式核心清單在隔離 checkout 的路徑與換行可攜性。核心運算檔的內容未變更；搬移檢查保留相同 SHA256 及來源／目的相對位置驗證。
