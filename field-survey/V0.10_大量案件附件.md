# 現況鑑定 V0.10.0：大量案件附件

本版範圍僅限現況鑑定模組。標準附件依每戶／公設單元輸出「整體平面圖 → 照片說明表 → 照片」，保留現場快速預覽。

## 建立名冊與分次進場

1. 建案後按「匯入戶別名冊」，從 Excel 複製含標題列的儲存格貼入，或選 UTF-8 CSV／TSV。欄位為「戶別、地址、棟別、種類」；戶別必填，種類為住戶／公設。每次最多 1,000 戶、2 MB。先檢查預覽；重複戶號及不正確欄位須修正後才能新增，不覆蓋既有戶別。不直接解析 XLSX。
2. 在上方選會勘批次，按「管理批次」新增或修改日期範圍。新位置帶入目前批次；單日批次預填該日，跨日批次的實際日期留白供確認。
3. 「戶別與本次進場情形」保存所選批次的狀態、進場日、觀察範圍與原因。歷次資料分開保留；修訂早期進場紀錄不覆蓋較晚批次的狀態。
4. 既有紀錄不自動指定批次，也不以建檔／匯入時間冒充會勘日。只知道批次範圍時，編輯畫面及快速預覽會標示逐筆日期未確認。V0.10.1 起，照片說明表不自動顯示逐筆及頁尾日期，頁尾只留頁碼；日期由後續簽名表單呈現。案件、備份與 JSON 對照仍保留會勘資料。
5. 「待補檢查」可依戶別／地址／棟別搜尋及篩選狀態，另列未確認日期與未選細圖。現場必要欄位待補仍獨立計算；一般現況、門牌等可選文字細圖，不必強制畫損害。

## 細部示意圖

在「附件整理」的每筆位置按「細圖」，選梁底仰視、梁柱交接、純牆面、有窗牆面、有門牆面或轉角牆面。選定後收起底圖選單，直接畫損害線、箭頭、圈選或文字；可刪除一筆、復原、重做及左右鏡射。沒有顯示圖層選單。

底圖僅含幾何線，不會把範例裂縫或推測尺寸帶入案件。也可選「門牌外觀、現況、詳平面示意圖、無須細部示意圖」，或上傳 JPG／PNG／WebP 底圖。損害標註另存為可編輯資料，自訂原檔保留在 `.csurvey`。

同一筆位置的遠拍／近拍共用細圖；若描述不同損害範圍，請分成不同位置紀錄。細圖會進入照片說明表，也能下載 PNG 貼到既有 Excel 表格。更換已有筆畫的底圖會先提醒清除筆畫；取消整個編輯視窗可保留原已存細圖。

## 附件與分冊

- 預設照片編號每戶由 001 重編，也可選全案連號。編號只在匯出時產生，不改寫原始照片或現場位置代號。
- 可選全案、單戶或勾選戶別，調整戶別順序及指定「本戶另起一冊」。住戶維持完整單元；公設選「依樓層分段」後可在樓層邊界分冊，同一公設的照片流水號仍連續。
- 版面設定提供每頁 1／2／3 張整體平面圖、照片說明表最多 8 列或自動排版、每頁 1／2 張照片。8 列為上限；長說明會減少列數或接續下一頁，完整保留內容。最後有空間時標示「以下空白」。
- 平面圖集中顯示跨房間的照片編號。密集代號自動錯開並用虛線連回原定位；原拍攝點和箭頭不移動。仍應核閱代號是否遮住底圖文字；圖面過密無法容納時會要求分區定位，不截掉代號。
- 可設定附件頁碼前綴，例如 `8-`，及起始頁碼。分冊後正文頁碼連續，目錄另行計頁。照片編號、圖上代號、說明表與照片頁使用同一份編號對照。
- 先按「規劃分冊」，只做文字與版面計算，不載入全案原始影像。選一冊後才產生該冊含圖預覽，可下載獨立 HTML、該冊 JSON 對照、全案分冊計畫及目錄 HTML。HTML 可離線開啟並列印為 PDF。
- 每冊正文頁數是分冊目標，不強拆一般住戶；單戶超出目標會明確標示。每次產生的影像副本合計上限 160 MB；實際超限須縮小範圍或減少選片。
- 勾選保留無照片單元時，輸出進場狀態頁，不產生虛構照片。補勘的既有照片仍保留，須自行核對本次選片。
- 附件整理每頁最多顯示 8 筆位置，縮圖進入可見範圍才載入。戶別檢查每頁 20 戶。排序／換頁前會保存人工修改的附件說明。

## 保存及界線

選片、主照片、人工文字、細圖與會勘資料保存在案件。匯出範圍、戶別排序和分冊版面設定為本次操作設定；重開後請重新核對，已下載 HTML／JSON 不會隨之變動。案件修改後須重新規劃分冊，避免把舊版頁碼套到新版內容。

資料庫及備份格式升為 5，仍讀取格式 1–4。舊視窗於升級後關閉資料庫連線，新版欄位不交由舊寫入器覆蓋。還原建立獨立副本，包含自訂細圖媒體與筆畫。現階段沒有跨裝置自動合併；兩台手機收集後的衝突核對與合併屬後續獨立階段。

裂縫寬度 mm、長度 m、面積 m²、磁磚塊數及梁 U 型裂縫條數維持不同語意。U 型不計總長，網狀不要求線性尺寸，≤0.3 mm 不自動換成既有報告的 W1 區間。附件只記錄觀察與量測，不產生安全評定或鑑定結論。

## 驗證與模組發布

```powershell
node --test field-survey/tests/model.test.js
node field-survey/tests/browser.test.js
node field-survey/tests/upgrade-v08.cjs
```

模型測試涵蓋分冊不拆戶、公共樓層排序、代號避讓、日期不確定性、細圖備份及既有裂縫語意。瀏覽器測試涵蓋名冊、兩次進場、細圖筆畫／刪除／復原／重做、自訂底圖、離線還原、多冊選片不重複不遺漏、頁碼及頁面溢出檢查。升級測試使用 Git 內實際 V0.7／V0.9 程式與服務工作者快取，核對原圖及圈註保存、舊寫入器拒絕及離線續填。

容量測試為 250 戶、500 筆位置、3,000 張不同的 240×160 合成 PNG 加 250 張平面圖；可規劃 2,250 正文頁，測試首冊及末冊影像匯出、載入量、資料不變及頁面無溢出。這不是 3,000 張手機原尺寸照片的記憶體或儲存量保證，尚未實測 iOS／Android 實機。

所有測試使用合成資料，私人參考報告不進入原始碼或網站。測試輸出位於忽略追蹤的 `output/field-survey-validation/`。

發布沿用 `Field survey module deploy` 工作流程，`release.mjs` 僅覆蓋 20 個現況鑑定執行檔，另產生模組發布收據。其餘既有網站檔案必須與固定基準逐位元組一致；原工具箱的全站驗證證據仍屬基準版次。完成部署後另執行 `node field-survey/release.mjs live` 核對線上版本、來源提交及 20 個檔案指紋；本機測試通過不等同已發布。
