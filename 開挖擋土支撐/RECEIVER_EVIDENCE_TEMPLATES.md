# 接收端受控補充證據範本

接收端回簽助手可把 RVR v5 五類補充查核中經常重複的文字與文件定位資料保存為本機受控範本。範本的用途是減少重複輸入，不是保存或替代正式證據；只有經本機核准且尚未過期的範本可以套用。

## 範本保存內容

- 補充查核類別
- 查核依據
- 文件編號
- 文件版次
- 文件日期
- 頁碼或章節
- 範本內容版號、逐版變更欄位與紀錄時間
- 本機審核人、核准時間與有效期限

範本明確不保存證據檔名及 SHA-256。套用範本後，該列會維持證據未完成狀態，使用者必須重新選取本案實際文件，由瀏覽器重新計算檔名與 SHA-256，才能建立 RVR。

## 核准與修訂流程

1. 在某一交接列將補充查核設為「通過」，填妥查核依據及文件受控欄位。
2. 按「儲存為範本／新修訂」。新範本固定從 v1、待核准開始。
3. 在範本卡填寫本機審核人與有效期限，再按「核准此範本」。有效期限不得早於核准日期。
4. 只有已核准且未過期的範本會出現在可用選單；可套用至個別查核或全部同類交接列。
5. 對每一列重新選取實際證據檔；範本不會帶入舊檔名或舊雜湊。
6. 套用後若修改查核依據或任一文件定位欄位再儲存，內容修訂會自動升版並撤銷核准，並列出變更欄位後要求重新審核。
7. 如需移轉至其他電腦，匯出 `receiver-supplemental-evidence-template-library` JSON，再於另一個瀏覽器匯入。外部檔案即使聲稱已核准，匯入後仍一律降級為待本機重新核准。

舊 schema v1 範本庫可繼續匯入或從既有 `localStorage` 載入，但會安全遷移為 v2 待核准範本，不會沿用舊版可直接套用的狀態。

## 安全與責任邊界

- 範本庫 schema v2 最多保存 100 筆，每筆最多保留 50 筆修訂紀錄，匯入檔上限 1 MB。
- 匯入時會驗證種類、版本、時間、日期、五類查核識別、版號、修訂順序、核准欄位及「不含檔名／雜湊」邊界；未知治理欄位、偽造額外簽章欄位、`fileName` 或 `fileSha256` 均會被拒絕。
- 核准資訊是目前瀏覽器的工作流程控制，不是數位簽章或組織身分證明；跨電腦匯入必須重新核准。
- 範本只保存在瀏覽器 `localStorage`，不會寫入來源專案、PDF、DOCX、ERH、RVR、SEV 或 SCV。
- 套用範本不是工程核可，也不證明文件仍為最新版或適用於目前案件。接收端仍須逐案核對模型、構造、版次、日期、頁碼及工程內容。
- RVR v5 仍要求每個標示通過的補充查核具有完整實際證據；SEV v2 仍由來源端逐檔重算 SHA-256。
